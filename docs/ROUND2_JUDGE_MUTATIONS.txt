WHY THIS FILE IS THE HONEST EVIDENCE
------------------------------------
Every guard in the judge reads a number that the fixtures publish correctly, so a
green run of the 49 tests proves only that the code and the fixtures agree. What
proves a guard can *fail* is the opposite: break the thing it watches and watch
the test that names it go red. The driver was written by the judge session and
**never executed** — before this run no claim existed that any judge guard can
fail, which is the same gap L15 was filed against for the gate docs.

METHOD
------
One mutant at a time, applied **in place**, the named test run, the outcome
captured, the original bytes restored in a `finally`. Each mutant's pytest run is
scoped with `-k` to the **one test that must fail**, so the battery is ~15 × 7 s
rather than 15 × 158 s. No mutation is committed. Every run used the containment
env (`WATCHDOG_SCRIPT`, `SUPERVISE_SCRIPT`, `ALGOFLOW_TEST_SESSION=1`) from the
tree under test.

THREE PATCHES THAT NEVER RAN (found before the first run)
---------------------------------------------------------
The driver as written could not have produced a single trustworthy verdict: three
of its fifteen patches did not apply or could not fire, and it reported rc from
the subprocess only, so a mutant that broke the *import* would have been counted
as a kill. All three were corrected before any result was recorded:

* **M1 targeted the wrong file.** It patched `judge.py` for
  `if slug == PAIRED_FLOOR_SLUG:`, which does not exist there — the judge
  deliberately holds **no second copy** of the routing rule and delegates to
  `screen.round2_precondition_stage`, where that comparison lives
  (`screen.py:868`). The mutant is re-pointed at `screen.py` (the driver's
  `TARGETS` map); its description is unchanged, because that *is* the guard it
  meant to kill. It bit on the first run.
* **M9's patch carried eight leading spaces where the landed line has four**, so
  it never applied. Re-pointed at the four-space line; it bit on the first run.
* **The driver counted "rc != 0" as a bite.** It now parses pytest's summary and
  FAILED/ERROR lines and only calls it BITES when the **named** test is in the
  FAILED list; an import/collection ERROR is recorded as ERROR, not a kill.

THE TWO MUTANTS THAT DID NOT BITE — kept, because they are the honest half
----------------------------------------------------------------------------
**M2 (v1) — BLIND, and not a guard hole.** As written it swapped the benchmark and
concentration *payloads* under fixed stage labels:
`_triple("benchmark", stages["concentration"])` and the mirror. On that test's
fixture **both** stages fail, so whichever payload sits in the benchmark slot is
still `False`, the label is still `"benchmark"`, and the bucket is unchanged —
`rc=0`. It also cannot be rescued by re-ordering the triples: `round2_bucket`
re-sorts them into `ROUND2_BUCKET_ORDER` and its own docstring says the input
order is irrelevant. The guard is fine; the mutant moved a number between two
identical values. **Re-pointed** at the swap that can move a *verdict*: benchmark
↔ `fat_tail`, the one stage that passes on that fixture. The benchmark slot then
carries a pass, the first failure in the declared order becomes `fat_tail`, and
the test fails. `rc=1` — BITES.

**M13 (v1) — BLIND, and not a guard hole.** It inserted
`if blocks < 3: return _result(False, "B < 3", ...)`. The test's whole point is
that `B` differs by a factor of four between its two grids — **168 vs 48** — and
both are ≥ 3, so the inserted branch could never fire and the code path was
byte-identical to the unmutated one. That is a mutant that does not mutate.
**Re-pointed** at `if blocks < 100:` — a gate that reads `B` at all — so the
48-block grid fails the headline while the 168-block grid does not, the two
buckets diverge, and `many["buckets"] == few["buckets"]` fails. `rc=1` — BITES.

**No guard in the judge was found blind.** Every one of the 15 guards has a
mutant that makes its own named test fail. No product code was changed by this
battery, so there is no prefix/postfix pair to record: the fixes above are to the
*driver* (how a guard is broken), not to the *guard*.
